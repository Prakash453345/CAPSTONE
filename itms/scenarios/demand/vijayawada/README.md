# Vijayawada corridor demand

`vijayawada_corridor.rou.xml`: 708 vehicles over a 30-minute window (0-1800s),
generated by `build.sh` (SUMO's `randomTrips.py`, seed 42, fringe-factor 5 so
trips actually traverse the corridor end-to-end rather than all being short
local hops). Regenerate with:

```bash
export SUMO_HOME=$(python3 -c 'import sumo, os; print(os.path.dirname(sumo.__file__))')
./build.sh
```

**This is not calibrated demand.** Build guide §8.5 calls for real
turning-movement counts, OD matrix estimation, and GEH-statistic validation
against observed link counts — that's real fieldwork, done once there's a
reason to defend the numbers (M3 baselines, M4 evaluation). This is
placeholder demand whose only job is to make M1's gate demonstrable: real
vehicles moving on the real network, visible on the dashboard at 1 Hz.
`notebooks/` picks up the calibration work when M8.5 needs it.

`vijayawada_corridor.sumocfg` ties this demand to the network in
`../../networks/vijayawada/` for `sumo`/`sumo-gui`/TraCI runs.
